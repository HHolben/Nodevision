# Phase M1 — Brown Hare

## A. Architecture

Brown Hare (`brown-hare`, *Lepus europaeus*, λαγώς) is the first built-in species. The canonical resource root remains **ApplicationSystem/public/BuiltIn/Mobs/**. No root-level BuiltIn directory, resource-serving endpoint or filesystem asset registry was added. Model URLs use the existing Express public static mount and bundled GLTFLoader.

Implementation modules under `ApplicationSystem/public/MetaWorld/Mobs/` separate responsibilities:

- Registry: declarative species metadata, public model/attribution URLs, dimensions, animation policy, habitat and defaults.
- Definition: validated authored object/configuration contract.
- Assets: reference-counted shared GLTFLoader request/decode and immutable resources.
- Rendering: per-instance model clone and procedural rigid-body animation; replaceable independently of behavior.
- Behavior: deterministic, reusable state decisions.
- Ground: bounded authoritative footprint and existing collision checks.
- Runtime: individual simulation state, update scheduling, visual ownership, picking/projectile collider and lifecycle.
- Authoring, Placement and Properties: adapters to the existing world/editor infrastructure.

The existing world scene, objects array, layer entries, history and save serializer own each authored `mob` object. There is no second mob instance registry. Species definitions identify a kind of animal; each object has its own stable UUID; shared model resources have neither authority over identity nor persistence.

The root mesh transform is the authored home. Its simulated body is a child, and the rendering adapter is below that body. Autonomous motion changes only runtime state/child transforms. Reopening restores home and restarts behavior. Saving, history and duplication never record velocity, navigation targets, timers, animation phase or the temporary simulated pose.

The OBJ references the existing MTL, which references Tex_Rabbit.png (32×32 RGB). OBJ/MTL/PNG are retained as source/fallback assets and are not loaded alongside the GLB.

## C. Editing integration

The closest established insertion category is **Insert → Game Object → Brown Hare**, alongside existing authored objects. The button identifies it as a built-in mammal. No new top-level toolbar was created.

Insertion reuses the existing camera placement workflow and its authoritative coverage/readiness/footprint checks. It refuses unsupported, unloaded, steep or rough surfaces rather than extending terrain coverage. The initial yaw faces toward the camera and remains authored; movement has its own temporary yaw.

Existing selection, translation/rotation/scale tools, grab, inspector, educational associations, duplicate/delete and undo/redo are integrated. The inspector exposes name, behavior/wander/flee/animation toggles, roaming/detection/flee radii, idle range and movement speeds, plus a species heading and attribution link. General transform controls are retained. Duplication creates a fresh ID and copies configuration/home/associations with the established small positional offset.

Behavior is suspended while inspected, grabbed or controlled by a transform gizmo. Suspension returns the representation to its authored home so the editor manipulates the persistent placement. Independent editing holds compose; closing one editor control does not release another active hold. Closing inspection/removing the gizmo releases its hold. Transform refresh updates the owned collider instead of replacing it with generic bounds. Positive scales are bounded to 0.05–10; invalid nonfinite transforms, negative speeds, invalid radii or inconsistent thresholds are rejected. Existing generic material editing does not replace the model's shared material.

Editor changes use the ordinary history and dirty mechanisms. Autonomous movement and impacts do not. Viewer mutations are rejected by the existing authoring bridge guard while simulation is permitted. Saved educational links survive reopening.

## D. Movement

Fixed simulation steps are 1/30 s, with a maximum of four steps per rendered update. Excess elapsed time is discarded and counted rather than producing a runaway catch-up loop. World pause clears accumulated work; disabled/hidden, actively edited, or more-than-64-m-distant mobs skip behavior/navigation. They retain identity/home without generating terrain or loading distant chunks.

The Ground adapter samples center plus four footprint offsets using existing authoritative sampleGroundY and collision interfaces. Queries have a local maximum height, not an infinite ray from above the world. Thus an overhead surface is not silently selected as ground. Geographic/map coverage and readiness are checked before sampling. No distant tile or vegetation proxy is used as ground. No map preparation or global path search is performed.

The per-step height allowance is 0.26 m times instance scale. Footprint height variation is limited, rejecting steep discontinuities, unsupported edges and pits. The existing player collision checker is reused with mob-sized body dimensions for terrain occupancy, caves/overhang clearance, constructions, imported solids and other mob boxes. Navigation stops/changes direction when support or clearance fails. It does not assume that a heightfield alone establishes body clearance.

The default broad body dimensions are radius 0.20 m, height 0.45 m, length 0.65 m, scaled with the instance. The ground reference remains authoritative; visible/body hop lift is layered above it. Hops have preparation, travel/airborne, landing and recovery portions. Movement is gated during preparation/recovery, accelerates toward the configured speed, and turns at a bounded rate instead of teleporting between destinations. Flee cycles are faster (0.40 s versus 0.65 s). Nominal hop heights are 0.09 m wandering and 0.18 m fleeing at Nodevision’s default flat gravity (0.012 reference-frame units, or 43.2 m/s²). The procedural hop amplitude responds to flat world gravity, including zero-gravity mode, rather than introducing another projectile simulator.

This is conservative local ground navigation, not a full animal rigid-body solver. Large drops are avoided rather than jumped or fallen into; point-mass/curved-surface locomotion is not implemented. Voxel-sized steps may still produce visible ground-height changes. Editing support out from under a stationary mob is not a supported falling simulation; reposition it onto valid ground. See K for further limits.

## E. Behavior

Decisions run at 5 Hz on fixed simulation time. Seeded randomness derives from stable instance identity, so fluctuating render cadence does not directly drive random choices.

| Setting | Default |
|---|---:|
| Behavior, wandering, flee response, animation | Enabled |
| Roaming radius | 8 m |
| Detection radius | 10 m |
| Flee radius | 5 m |
| Idle/graze duration range | 2–5 s |
| Wander speed | 1.2 m/s |
| Run speed | 4 m/s |
| Local simulation distance | 64 m |

Movement speeds are cycle targets; preparation/recovery gating reduces average travel speed. Idle alternates with grazing and bounded destinations sampled within the home radius. A blocked or expired wandering goal yields an idle cooldown instead of continuously retrying it. Wandering enforces the home radius; a hare displaced by fleeing can move back inward.

Player proximity causes Alert, then Fleeing when inside the flee threshold. Flee direction is away from the local player; blocked paths rotate the steering direction. Fleeing continues at least 1.5 s after the last close threat and until the player is beyond detection radius +2 m. Recovering lasts 2 s before normal activity resumes. Alert releases beyond detection radius +1 m. These margins/cooldowns prevent threshold oscillation. Detection uses world-space distance, without full line-of-sight, hearing or scent. Networking/multiplayer perception is deferred; the current local player is the threat source.

## F. Rendering and animation

Each live species lease shares one GLB request/decode, geometry, material and texture. Per-mob clones own transforms; imported geometry is never modified. Pending deletion is handled: a late model completion cannot attach to a disposed mob, and the final lease releases shared resources. Failures resolve to a useful console/inspector error and false readiness, with no unhandled promise rejection. Model-less logical objects remain editable/removable.

This rigid mesh has no safe independent ear/limb controls. Whole-body pitch, subtle idle scale variation and a moving body lift provide grazing/hopping/running. There is no fabricated skeleton, clip mapping or per-frame geometry rebuilding. The adapter boundary permits future sprite, skeletal or wildlife LOD renderers without replacing identity or behavior; these renderers are not implemented in M1.

Deleting a mob, undo reconstruction, world reload or GameView closure releases its collider, visual lease and private proxy resources. Shared resources survive until their final owner is gone. No per-mob interval or timeout is created.

## G. Interaction and diagnostics

Picking resolves the authored root; projectile collision uses the moving body’s transformed world bounds. This intentionally conservative box is a hit approximation, not triangle-accurate anatomy. Embedded arrows attach to the moving body and are removed when the mob is deleted. A hit never automatically destroys the mob or changes health/source data.

The existing bow owns all projectile flight and first-impact logic. It emits the established arrow event and includes interpreted `mobHit` data. The GameView panel additionally dispatches **`mob-hit`** with mobId, speciesId, arrowId, shooterId when available, world point/normal, incomingVelocity, simulationTime, launchForce/speed and flight duration/distance. No injury, blood, death or harvesting is implemented.

Existing terrain picking, construction, target and teleporter paths are retained. The production mob scenario also activates the existing teleporter with hare colliders resident in the same world; its separate regression covers trusted input. Separate production regressions exercise the bow, target and teleporter, including imported solids and terrain representations.

Selected-object diagnostics are available through `object.userData.mobRuntime.snapshot()`: state, position, editing flag, steps, behavior/movement CPU, animation CPU, ground/clearance query counts, navigation failures, discarded time, model triangles and load error. Counters are updated during actual work; there is no permanent mob panel or per-frame diagnostic enumeration.

## H. Performance

[Raw benchmark](MobM1Performance.json): actual installed GLB rendered by Chromium/SwiftShader at 640×480. Each of 1/5/20/50 hares is measured with behavior enabled and disabled, with 30 warm-up and 240 measured RAF frames, in two reversed-order trials (**16 cases**). Active cases use 0.1–0.2 s idle durations to exercise movement within the measurement window; flee is off and the authoritative ground fixture is flat. These are repeatable component measurements, not a populated-world FPS guarantee.

The following values average the two trials; p95 entries average trial percentiles rather than pooling samples.

| Hares | Enabled | Mean / p95 frame ms | Mean / p95 total update ms | Draws | Triangles |
|---:|:---:|---:|---:|---:|---:|
| 1 | No | 16.665 / 17.050 | 0.038 / 0.100 | 1 | 674 |
| 1 | Yes | 16.667 / 17.100 | 0.111 / 0.300 | 1 | 674 |
| 5 | No | 16.666 / 17.100 | 0.048 / 0.100 | 5 | 3,370 |
| 5 | Yes | 16.667 / 17.150 | 0.205 / 0.450 | 5 | 3,370 |
| 20 | No | 16.667 / 17.150 | 0.082 / 0.200 | 20 | 13,480 |
| 20 | Yes | 16.666 / 17.000 | 0.456 / 0.850 | 20 | 13,480 |
| 50 | No | 16.666 / 17.000 | 0.122 / 0.200 | 50 | 33,700 |
| 50 | Yes | 16.666 / 17.000 | 1.051 / 2.350 | 50 | 33,700 |

At 50 enabled hares, mean fixed simulation/ground work is 0.602 ms per frame and mean animation/pose/bounds work is 0.250 ms; total update additionally includes scheduling, transform checks and distance checks. Approximately 20,508 support-height queries occurred per trial including warm-up; each footprint uses five queries, so approximately 4,102 clearance/navigation samples. The raw records include rejection counts and every size’s query totals. Disabled cases make zero navigation/ground queries.

All sizes share **one model geometry and one texture**, with **46,668 bytes** of model attribute/index storage. Each instance additionally owns a small private collision proxy (840 typed bytes), its transforms/controller state and material wrapper. Texture/driver/JS heap memory is not measured by that geometry byte count. After each case, renderer geometry and texture counts return to zero. One visible model is one draw; global instancing and distant wildlife LOD are deferred.

The frame clock is near the 60 Hz pacing limit; tiny differences between counts/enabled states are not evidence of an FPS speedup. Hardware GPU/Electron and full terrain+vegetation contention were not measured. Navigation cost depends on existing collider count/complexity; a complex imported collider scene may cost more than this flat benchmark. There is no claim that 50 hares are free or that the previous distant-terrain FPS deficit is resolved.

## J. User walkthrough

1. Open a world in Virtual World Editor and aim at supported loaded ground.
2. Choose **Insert → Game Object → Brown Hare**.
3. Inspect it to change name, roaming radius, proximity thresholds, speeds, behavior and animation toggles. The species and attribution link are shown in the same inspector.
4. Use ordinary move/rotate/scale controls or grab. While editing, the hare returns to its saved home and its autonomous motion is suspended.
5. Close Inspect / Modify and remove any active transform tool to observe idle/grazing/hopping. Stay beyond its detection radius to observe calm wandering, then approach to trigger alert/flee.
6. Use the inspector’s duplicate/delete actions; undo/redo applies to authored changes.
7. Save normally. Reopen to restore each hare at its authored home. Viewer permits simulation but blocks persistent changes.
8. Equip the existing Archery Bow where inventory policy permits. Hits emit mob-hit and can leave attached arrows; no health/death behavior occurs. The local attribution notice remains accessible from the inspector.

## K. Remaining work

Natural spawning/populations, additional species, habitats/ecology, predator–prey behavior, multiplayer perception, health and lesson systems are deferred. So are global pathfinding, species-specific physics, jumping gaps, falling into edited pits, point-mass/curved-world locomotion, limb/ear animation, sprites and wildlife LOD.

Current navigation is local and conservative. It may stop or turn repeatedly around an impassable feature; it does not solve routes around large barriers. Fleeing can exceed the home radius, while later wandering permits an inward return. Source readiness/NoData checks can pause navigation at unloaded or unsupported regions. Authored mobs use existing object residency and freeze beyond 64 m; no separate streaming/population manager is added.

Selection intentionally returns a simulated hare to its authored home; editing at the temporary roaming position is not implemented. Geometry-scale changes and a coarse body box are adequate for this initial consumer, not anatomical collision. Ground transitions on voxel stairs can remain visually coarse. Hardware deployment tests, detailed heap/driver profiling and combined large-world benchmarks remain future validation work.
