# Physical Path placement

Insert → Path and the inventory **Path** item activate `PathTool.activatePathTool`, which prepares the existing editable-world bridge and starts `PathInteraction.beginPathDrawing`. The previous callback silently returned false unless the global mode string exactly matched one of two values; it also assumed a bridge and canvas already existed. Activation now checks actual authoring permissions, initializes the bridge when needed, resolves the active renderer canvas, and reports failures in the status bar. Selecting Path from the existing inventory activates the same controller and updates the contextual cursor toolbar. The item uses `icons/PathTool.svg` and the existing slot assignment controls.

While holding Path, **right-click** terrain to place the beginning, then **right-click again** to place the endpoint and commit a segment. The tool stays active for additional segments. In pointer-lock mode it uses the center crosshair; otherwise it uses the pointer. Right-click an existing path at either end of the new segment to join its centerline, including branch junctions, at the same surface height. Joined segments preserve those authored elevations. Holding the use button does not repeat placement. A marker previews the first point, and a width-aware ribbon previews the segment. Left-click multi-point drawing remains available: Enter or double-click commits one history transaction; Backspace removes a draft point; Escape discards the current draft. Switching inventory tools or panels suspends the draft while its world bridge remains alive. Returning to Path resumes it. Drafts are transient and do not survive closing the world or rebuilding its bridge.

G opens width, surface, straight/smooth/mixed geometry, mixed-segment type, elevation mode/offset, terrain modification, smoothing, edge blending, and terrain/grid/endpoint snapping. Existing paths use the normal inspector: drag or numerically edit control points (authored/locally-flat dragging preserves elevation; terrain-following dragging samples terrain), insert/remove points, change properties, extend, or delete. Extension edits the same object and is undoable. Dirt uses the existing soil material; paved uses the existing stone material with a smooth surface. Custom values are canonical Nodevision material IDs, and material-load errors appear in the inspector.

Paths remain `physical-path` world objects. `PathDefinition`, `PathGeometry`, `PathRuntime`, `PathAuthoringBridge`, and `PathTerrainField` retain their existing roles. Definitions persist points, position, width, interpolation/mixed segment choices, material, elevation mode and offset, smoothing, terrain interaction, transition width, snap settings, visibility, collision and vegetation exclusion. Old definitions retain their authored/follow-terrain behavior and default smoothing of zero. Save/reopen, Play transitions, object selection, deletion, and undo/redo use the normal world pipeline.

Locally-flat mode smooths local control-point elevations without forcing a single global height. Ribbons have flat cross sections and preserve the overall incline. Grading uses the existing deterministic cut/fill field over the original generator, restricted to path corridors and transition bands. Streaming, regeneration, and history restoration reapply constraints; they do not cumulatively deform already modified terrain. In legacy grading mode, the rendered surface and walking collider share ribbon triangle heights, with a small surface offset to avoid z-fighting. Excavation instead uses voxel floors and clipped bridge triangles. Overlay/none leave voxel heights unchanged; vegetation exclusion remains a separate existing path property.

Command interface: `path.world` actions are `activate`, `settings`, `finish`, `cancel`, `create`, `update`, `extend`, `delete`, and `clearance-preview`. The second argument is an options object; create accepts `controlPoints` and the persisted properties, update/delete/extend identify an existing path by `id`. These are available through the existing terminal command registry, alongside keyboard and GUI interactions.

Separate paths can cross, and grading is ordered deterministically. Clicked junctions share centerline coordinates and authored elevations; automatic junction meshing and route/pathfinding networks are not introduced. Self-crossing individual ribbons and turns too tight for their width are rejected with feedback. Edge blending controls the terrain grading transition, not a new translucent edge shader. A material-thumbnail preview is not added.

Smooth geometry follows a continuous centripetal curve through the control points, including smooth segments in mixed paths. Smoothing controls elevation averaging in locally-flat and follow-terrain modes; it does not blend curved turns back toward sharp control-polygon corners. Actual self-crossings and turns too tight for the chosen width still produce validation errors.

Validation: `Paths.test.mjs` covers legacy definitions, ribbons, local smoothing, mixed geometry, collision-height queries, corridor bounds, cut/fill, chunk queries and idempotent regeneration, including three- and four-point turns across smoothing settings. `scripts/paths-browser.mjs` covers Enter completion of those turns with default settings, real streamed voxel terrain, toolbar/inventory activation, G settings, draft suspension/resume, extension, properties, history, save/reopen, Play authoring restrictions, materials and rendered pixels. `scripts/paths-native-input.cjs` adds real Electron right-click start/end placement, branch joining, mouse/keyboard drawing and control-point drag/undo checks through the existing browser runner. Voxel World and shared model suites check neighboring inventory tools.

Run `python3 scripts/test-paths-browser.py` for the integration suite and trusted Chromium mouse/keyboard checks (including two right-click placement, joining, and undo/redo). Run `node --test ApplicationSystem/public/MetaWorld/Paths/Paths.test.mjs ApplicationSystem/public/MetaWorld/Paths/PathJoin.test.mjs` for geometry and junction projection checks.

Terrain-aware excavation, four directional clearances, supported voxel roadbeds, and unsupported bridges are described in [Path terrain modifiers](PathTerrainModifiers.md). New paths default to excavation; old saved grading behavior is preserved.
